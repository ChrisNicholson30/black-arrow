# Syncing with upstream Codex

Black Arrow is a shallow fork of [openai/codex](https://github.com/openai/codex). Upstream moves quickly, and the fork is only worth having if its improvements can be taken regularly without drama. This page is the procedure.

## Remotes and branches

```text
origin    Black Arrow
upstream  https://github.com/openai/codex.git   (fetch only)
```

`upstream` tracks one branch, `main`. Upstream has several thousand other branches, and fetching them all adds nothing but clutter. Pushing to `upstream` is disabled. To set up a fresh clone the same way:

```bash
git remote add upstream https://github.com/openai/codex.git
git config remote.upstream.fetch '+refs/heads/main:refs/remotes/upstream/main'
git remote set-url --push upstream no-push
git fetch upstream
```

| Branch | Purpose |
|---|---|
| `main` | Released Black Arrow. Until the first release it stays at the commit Black Arrow forked from. |
| `develop` | Integration branch. Work lands here first. |
| `upstream-sync` | Where upstream is merged and repaired before it reaches `develop`. |

Open pull requests against `develop`, each from its own branch. Do not base one pull request on another's branch: if the lower one is merged first, the upper one merges into a branch nobody will merge again, and its changes go nowhere. A branch that builds on unmerged work can still target `develop`; its diff simply includes the earlier commits until they land.

## Why merges stay cheap

Most of what differs from upstream is mechanical, and each kind has a rule a script can re-apply:

| Difference | Rule | Where |
|---|---|---|
| Files Black Arrow does not carry | Deleted again whenever upstream changes or adds them | `scripts/blackarrow/pruned-paths.txt` |
| Files Black Arrow writes itself | Black Arrow's version always wins | `scripts/blackarrow/owned-paths.txt` |
| `codex …` in messages that tell the user what to run, and the other text rules | Rewritten by a codemod | `scripts/blackarrow/rebrand_command_hints.py` |
| Conflicts in files only the codemod changed | Upstream's side is taken, then rewritten again | `scripts/blackarrow/upstream_sync.py merge` |
| Snapshot files named after the binary crate | Renamed from `codex__*` to `blackarrow__*` | same |
| Snapshot contents that show product text | Regenerated by running the tests | `INSTA_UPDATE=always`, then `tidy-snapshots` |

What is left is the set of deliberate code changes described in [architecture.md](architecture.md). Each one is marked in the source, either with a `Black Arrow:` comment saying why it is there or by a call into `blackarrow_base`, and `upstream_sync.py check` fails if a hand-changed upstream file carries no such mark. Those are the only conflicts that need a person.

To see how large the difference is at any time:

```bash
scripts/blackarrow/upstream_sync.py footprint          # counts
scripts/blackarrow/upstream_sync.py footprint --list   # and the hand-changed files
```

Watch the "changed by hand" number. If a sync makes it grow, something that should have been a rule was done by hand.

## Procedure

Start from a clean tree.

```bash
git fetch upstream
git switch upstream-sync
git merge --ff-only develop        # bring the sync branch up to date with Black Arrow

scripts/blackarrow/upstream_sync.py merge upstream/main
```

The script merges without committing, removes pruned paths, restores owned paths, takes upstream's side of conflicted snapshots and of files that only the codemod had changed, renames binary-crate snapshots, re-runs the codemod, and prints whatever is still conflicted.

Then:

1. **Resolve what it lists.** For each file, find the `Black Arrow:` comments on Black Arrow's side and carry that change onto upstream's new code. If upstream has removed the code a change applied to, check whether the change is still needed.
2. **Build.**
   ```bash
   (cd codex-rs && cargo build --bin blackarrow)
   ```
3. **Refresh snapshots, then tidy and review them.**
   ```bash
   INSTA_UPDATE=always scripts/blackarrow/test.sh -p codex-tui -p codex-cli
   scripts/blackarrow/upstream_sync.py tidy-snapshots
   git diff --stat -- '*.snap'
   ```
   A refresh rewrites more than it should. `tidy-snapshots` puts upstream's header back on every snapshot the refresh touched and restores the ones whose contents did not change, so what remains is real.

   Read what remains. Expected differences are upstream's own UI changes with Black Arrow's name, prompt text, and command names in place of Codex's. Two things are not expected:

   - **A timer or spinner difference**, such as `Working (0s` becoming `Working (2s`. That is a test that ran slowly on a busy machine, not a code change. `tidy-snapshots` lists these and exits non-zero. Restore each file and re-run its test on its own.
   - **A different message or screen.** A refresh will happily record a wrong result. If a snapshot now shows something else entirely, a test's expectation and the product disagree; fix that, do not accept the snapshot.
4. **Run every test without refreshing.**
   ```bash
   scripts/blackarrow/test.sh
   ```
   See [Running the tests](#running-the-tests) for what to make of failures.
5. **Check the rules hold.**
   ```bash
   scripts/blackarrow/upstream_sync.py check
   ```
   Besides the mechanical rules, this catches two ways a merge undoes the fork without a conflict: a hand-changed file that has lost its `Black Arrow:` note, and a default in `blackarrow/base/src/defaults.rs` that no upstream file reads any more because the call was merged away.
6. **Measure.** A sync must not make startup slower or add network requests.
   ```bash
   (cd codex-rs && cargo build --release --bin blackarrow)
   scripts/blackarrow/bench_startup.py --bin codex-rs/target/release/blackarrow
   scripts/blackarrow/terminal_check.py --bin codex-rs/target/release/blackarrow
   ```
   Compare against [performance.md](performance.md), including the list of hosts.
7. **Commit the merge**, then merge `upstream-sync` into `develop`.

## Things to look for in every sync

The scripts cannot catch these. They are how a merge quietly undoes the fork.

- **New state locations.** Any new environment variable, directory under the home directory, path under `/etc`, Keychain service, or macOS preferences domain with `codex` in its name. Each needs a Black Arrow equivalent in `blackarrow/base/src/paths.rs` or `brand.rs`.
- **New network calls at startup.** Run the benchmark and read its "Network attempts" section. A new host is a new decision.
- **New sandbox-protected paths.** If upstream adds to `PROTECTED_METADATA_PATH_NAMES`, check that `.blackarrow` is still in the list and that the tests in `sandboxing/src/seatbelt_blackarrow_tests.rs` pass.
- **Feature defaults.** `features/src/blackarrow_tests.rs` fails if a default Black Arrow turned off has come back on.
- **New commands that act on a Codex install**, in the way `update` and `app` do.
- **New user-visible strings** naming Codex in primary surfaces: `--help`, the session header, onboarding, the doctor.
- **New drawings of upstream's logo.** `tui/tests/suite/blackarrow_screen.rs` checks the first screen; a new place would need its own check.
- **A new V8 version.** Upstream adds a checksum manifest under `third_party/v8/` when it changes the `v8` crate. The prune rules keep that one file; check that it arrived, or `fetch_v8.py` will refuse to download.
- **The Codex client version.** Set `CODEX_CLIENT_VERSION` in `blackarrow/base/src/upstream.rs` to the newest upstream release the merge contains. A release is contained when the `main` commit it was cut from is in the merge. This finds it, newest first:
  ```bash
  merged=$(git merge-base HEAD upstream/main)
  for tag in $(git ls-remote --tags upstream 'rust-v*' | grep -oE 'rust-v[0-9]+\.[0-9]+\.[0-9]+$' | sort -rV | head -10); do
    git fetch -q upstream "refs/tags/$tag:refs/tags/$tag"
    git merge-base --is-ancestor "$(git merge-base upstream/main "$tag")" "$merged" && { echo "$tag"; break; }
  done
  ```
  Too low, and the backend hides and refuses its newest models without saying why. Too high, and Black Arrow claims to be a client it has not merged. The bundled catalogue is not the guide: its `minimal_client_version` values understate what the backend wants. `blackarrow_client_version_tests` in `codex-models-manager` still fails if the constant is below what the catalogue asks for.

## Running the tests

Always use `scripts/blackarrow/test.sh`, never bare `cargo test`. Upstream ran its suite through a `just test` recipe that Black Arrow does not carry, and the suite depends on what that recipe set up. The script supplies it:

- **`cargo-nextest`**, with upstream's configuration in `codex-rs/.config/nextest.toml` and Black Arrow's additions in `scripts/blackarrow/nextest.toml`. Install it once with `cargo install --locked cargo-nextest`.
- **An 8 MiB thread stack.** With the default, tests that load configuration in a debug build overflow the stack and spin forever instead of failing.
- **A throwaway home directory**, so tests that launch the program do not write into your real `~/.blackarrow`.
- **No network.** Otherwise every test that starts the app server fetches OpenAI's plugin repository from GitHub and asks chatgpt.com for the model list. `BLACKARROW_TEST_NETWORK=1` turns this off.
- **Upstream's defaults**, through `BLACKARROW_UPSTREAM_DEFAULTS=1`, because upstream's tests were written against them.

Run the whole workspace before a merge is committed, with no `-p` at all, as upstream's recipe did:

```bash
scripts/blackarrow/test.sh
```

A subset is fine while working, but tests in one crate use helper binaries built from another, and with `-p` those are not built: the tests that need them fail with "could not locate binary". The one crate left out of a whole run is `codex-voice-host`, which needs GStreamer installed and is not part of what Black Arrow ships.

The first run downloads upstream's prebuilt V8, 24 MB, which the code-mode host is built against. `scripts/blackarrow/fetch_v8.py` verifies it against the checksum manifest in `third_party/v8/` before the build may use it. Offline, the code-mode host and the tests that start it are left out, with a message saying so.

Tests must be built with debug assertions, which is the default. See "Upstream names in debug builds" in [architecture.md](architecture.md).

On macOS, expect a few failures in a full run of `codex-tui` that are not regressions:

- Tests that render a status line with an elapsed-seconds counter or a spinner (the `guardian` and `active_reconnect` snapshot tests) fail when the machine is busy.
- Tests that start several embedded app servers can exceed the 60-second limit, because macOS serves all file watchers from one daemon. Black Arrow's nextest additions run them four at a time, which removes most of these.

- A few core tests give an operation five seconds, or MCP startup 250 ms (`hooks_mcp`, `mcp_optional_startup_grace`). They fail on a busy machine. One of them, `zero_grace_respects_server_startup_timeout`, has also failed in a test binary built together with other packages while passing in one built with `-p codex-core` alone, at the same commit. Unmodified upstream passes built that second way; it has not been compared built the first way.

Re-run anything that fails on its own before believing it:

```bash
scripts/blackarrow/test.sh -p codex-tui -E 'test(=the::full::test::name)'
```

A failure that survives that is real.

## What has been exercised

`check`, `footprint`, `prune`, and `tidy-snapshots` are used on every change.

`merge` has been run once, against a synthetic upstream commit built to hit every rule. The outcome, which is what a real sync should look like:

| Synthetic upstream change | Result |
|---|---|
| Edited `justfile`; added a directory under `sdk/`; added a `BUILD.bazel` | Removed again |
| Edited `README.md`; added a file under `docs/` | Black Arrow's README kept; the new file dropped |
| Reworded a message the codemod had rewritten | Upstream's wording taken, then rewritten: no conflict |
| Added a new `codex login` hint in a new file | Rewritten to `blackarrow login` |
| Changed a snapshot Black Arrow had refreshed | Upstream's taken, to be refreshed by the tests |
| Changed a snapshot Black Arrow had renamed | Change carried into the renamed file |
| Added a new `codex__*` snapshot to the CLI crate | Renamed to `blackarrow__*` and rewritten |
| Edited a manifest Black Arrow also edited, on other lines | Merged cleanly |
| Edited the lines Black Arrow changed in `utils/home-dir/src/lib.rs` | Reported as needing a person |

It has not yet met a real upstream change, because upstream had not moved when the foundation was committed. Expect to adjust it during the first real sync, and record what changed here.
